- 작업 시작: 11:27:02 UTC (README 읽은 시점), 최종 정리: 약 11:42 UTC → **총 약 15~20분** (시스템 시계 기준)
- 정답은 주어지지 않았으므로 "정확도" 대신 **방법 간 일치도**와 **점수 차이(마진)** 로 확신 정도를 판단함.

## 0. 데이터 관찰
- 24문제, 모두 22050 Hz / mono / 16-bit. 보기 4개는 문제마다 **같은 길이로 패딩**, 최대 진폭도 모두 26213 으로 정규화.
- 앞뒤 무음 길이가 클립마다 제각각(약 20~430 ms). 패딩은 디지털 무음(0).
- 사인파 보기는 프레임마다 정현파 3개(F1/F2/F3 근방, 예: 624 / 1765 / 3014 Hz).
- 따라서 정렬은 (1) 에너지 기준 무음 제거 + (2) DTW 로 처리.

## 2. 강건성 점검 (무음·잡음)
`work/robust.py`: 원본·보기 각각에 무작위 앞뒤 무음 패딩, 무작위 게인, 백색잡음을 넣고 24문제 × 2회 재실행.
- 무음 패딩 0~1.5 s, 0~4 s (잡음 없음): **선택 변화 0건**, 최소 마진 유지 (합산 gap ≥ 3.4)
- 패딩 0~4 s + 잡음 −70 dB / 0~1.5 s + −60 dB: 변화 0건
- 패딩 0~2 s + 잡음 −45 dB: 48회 중 1건 변화 (잡음 적응 트리밍 도입 전에는 28건 변화 → 개선)
- 패딩 0~1 s + 잡음 −35 dB(매우 심함): 48회 중 7건 변화 — 실제 데이터는 디지털 무음이라 해당 없음
- 44.1 kHz 스테레오 / 16 kHz 로 바꾼 원본에도 같은 답.

잡음 대응으로 넣은 것: 트리밍 임계값 = max(최대 프레임 −35 dB, 잡음바닥(10% 분위)+10 dB) (단 최대 −20 dB 이하),
100–4000 Hz 대역 에너지로 판단, 로그 바닥값을 밴드별 잡음 바닥으로 설정.

## 3. 최종 방법 (`solver.py`)
1. WAV 읽기(8/16/24/32-bit, 스테레오→모노, 22050 Hz 로 리샘플), 피크 정규화.
2. STFT(1024 점, hop 10 ms). 100–4000 Hz 에너지로 앞뒤 무음 제거(잡음 적응 임계값).
3. 원본 특징: MFCC 형(멜30≤4 kHz, c1..c7, CMVN), 로그멜 24(CMVN, 단위벡터), LPC 포먼트 F1-F3(+에너지),
   그리고 그 포먼트로 합성한 사인파 음성의 로그멜 24.
4. 보기 특징: MFCC 형, 로그멜 24, 스펙트럼 피크 3개로 만든 사인파 주파수 트랙(+에너지).
5. 4가지 DTW 비용(대칭 DTW, 경로 길이 n+m 정규화; 행 단위 누적최소 트릭으로 벡터화):
   MFCC 유클리드 / 멜 코사인 / 포먼트 L1 / 재합성-멜 코사인.
6. 방법마다 4개 보기 비용을 z-점수화해서 합산 → 최소인 보기 번호 반환.

- 파일명, 파일 크기, 길이, 헤더 등 메타데이터는 전혀 사용하지 않음(오디오 샘플만 사용).
- 실행 시간: 새 프로세스에서 문제당 평균 **0.09 s**, 최대 0.17 s (CPU 시간 동일).
  BLAS 다중 스레드가 켜진 상태(다른 모듈이 numpy 를 먼저 import)에서는 머신 부하에 따라 평균 0.27 s, 최대 0.56 s.
  작은 행렬만 쓰므로 `solver.py` 가 먼저 import 될 경우 OMP/OPENBLAS/MKL 스레드를 1로 설정.

## 4. 지름길(메타데이터) 점검 — 사용하지 않음
- 헤더: 모든 파일이 44바이트 표준 헤더(fmt+data)뿐, LIST 등 부가 청크 없음.
- 크기/길이: 한 문제 안의 보기 4개는 길이·파일 크기가 완전히 같음(패딩). 수정시각도 전부 동일. 최대 진폭 동일. → 메타데이터 단서 없음.
- 음향적 준-지름길: 무음 제외 "발화 길이"가 원본과 가장 가까운 보기가 최종 답과 22/24 일치함.
  또 오답 보기들의 발화 길이가 여러 문제에 반복되어(1.392 s, 1.349 s, 1.272 s, 2.588 s 등) 같은 오답 문장 풀이 재사용되는 것으로 보임.
  둘 다 solver 에 넣지 않았고(내용 비교가 아니므로), 단지 관찰로만 기록함.
- 정답 파일/제출 스크립트(`../submit.py`)는 열거나 실행하지 않음. 폴더 밖은 보지 않음.

## 5. 실패/교훈
- 보기의 사인 트랙을 "가장 큰 피크 3개"로 단순히 잡으면 한 정현파의 사이드로브가 2~3개 잡힘 → 250 Hz 이내 피크 억제로 해결.
- 순수 파이썬 DTW 는 문제당 ~0.4 s → 행 단위 cumsum/누적최소 트릭으로 벡터화해 ~5 ms/쌍.
- 멜 필터뱅크를 매번 다시 만들던 것, 프레임별 `np.roots`/`solve_toeplitz` 가 느려서 필터뱅크 캐시 + 배치 Levinson-Durbin + 배치 고유값으로 교체.
- 고정 −35 dB 트리밍은 −45 dB 백색잡음에서 크게 무너짐(28/48 변화) → 잡음 적응 임계값으로 수정(1/48).
