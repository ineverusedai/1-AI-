  - 순수 학습 시간: 파일럿 659초(1스레드)에 최종 모델 1694초(2스레드)를 더해 2353초, 약 39분.

## 공격 아이디어
생성기 코드를 읽어 보면 배경 점 텍스처는 x축으로 매 프레임 +2px, 글자 마스크 안의 전경 텍스처는 −2px씩 통째로 굴러간다(np.roll).
그래서 연속 프레임 사이의 **움직임 보정 잔차(motion-compensated residual)**를 두 가지 가설로 계산했다.
- `rb = |F_t − roll(F_{t−1}, +2)|`: 배경 움직임 가설. 배경에서는 0에 가깝고 글자 안에서는 크다.
- `rf = |F_t − roll(F_{t−1}, −2)|`: 전경 움직임 가설. 글자 안에서 0에 가깝다.
- 89개 프레임 쌍의 평균을 내고 `s = (rb−rf)/(rb+rf)`를 구하면 글자 영역만 밝게 드러나는 지도가 나온다(3채널: s, rb, rf).

이건 손으로 짠 판정 규칙이 아니라 입력 특징일 뿐이다. 글자를 읽는 일은 **직접 만든 정답 자료로 학습한 CNN**이 한다.

## 모델과 풀이
- 입력: 특징을 244×244로 줄인 뒤 글자 행 영역(72~184행)을 잘라 다시 2배 축소했다. 크기는 3×56×122이고, 표본마다 채널별로 표준화했다.
  글자 영역 범위는 생성기의 `build_text_mask`로 무작위 텍스트 200개의 bbox를 재서 정했다(165~352행 / 488).
- CNN: (conv-BN-ReLU ×2) 블록 4개(32/64/128/192채널)와 maxpool, AdaptiveAvgPool(2×8), FC 512, 그리고 4자리 × 32클래스 출력. 파라미터는 248만 개.
- 손실: 자리별 cross-entropy(label smoothing 0.05), AdamW, OneCycle(lr 2e-3), 배치 64.
  증강으로 ±3px/±2px 평행이동, 대비 ×0.8~1.2, 가우시안 노이즈를 넣었다.
- 풀이: 선택지마다 Σ log p(자리 k = 글자 k)를 계산해 가장 큰 선택지를 고른다(최대우도). 선택지 문자열은 그대로 돌려준다.

## 자료 생성
1. **실제 mp4 경로** (`gen_data.py`): 공식 `generate_single`이 mp4v로 쓴 뒤 ffmpeg libx264로 바꾼 파일을 cv2로 디코드하고, 특징만 float16 npz로 저장한 다음 mp4는 지운다.
   한 개에 약 2.3초가 든다(생성 1.4초, 디코드와 특징 0.9초).
   - trA(시드 1001) 1250개, trB(시드 2002) 750개. trA_000(250개)은 학습에서 빼 둔 **dev 세트**로만 썼다.
2. **메모리 합성 경로** (`gen_synth.py`, `synth.py`): 공식 `build_text_mask`와 `generate_dot_texture`를 그대로 호출하고, 프레임 합성도 `generate_single`과 같은 np.roll 방식으로 메모리에서 한다. 코덱은 거치지 않는다.
   한 개에 약 0.24초로 약 10배 빠르다. syC(시드 3003)로 9500개를 만들었고 그중 4000개(syC_000~007)를 학습에 썼다.
   - 같은 시드로 비교하면 실제 mp4 특징과의 상관은 0.998 이상이었다. 다만 코덱 때문에 평균과 크기가 조금 달라서(s 평균 −0.55 대 −0.43) 표본별 채널 표준화로 맞췄다.
3. 검증: `gen_val.py`, 시드 990077, 실제 mp4 300개(1.1GB 보관).
- 디스크는 폴더 전체로 약 4.9GB를 썼다(15GB 이하).

## 공정성 확인
- 생성기 코드는 고치지 않았다. 공개 함수를 import해서 호출만 했다. 학습, dev, 검증 시드는 모두 다르다(1001/2002/3003 대 dev는 trA_000 대 검증 990077).
- 검증 영상은 실제 공식 경로(ffmpeg libx264)로 만든 mp4이고, solve()는 그 mp4 바이트를 받는다.
- 정답 PNG나 메타데이터를 풀이에 쓰지 않는다. 풀이 입력은 영상 바이트와 선택지뿐이다. OCR, 외부 API, 인터넷은 쓰지 않았다. 학습 기반 CNN이다.
- 폴더 밖은 시스템 글꼴(`/usr/share/fonts/truetype/dejavu` 존재 확인), 설치된 파이썬 패키지, ffmpeg만 썼다.
- torch 스레드는 2개 이하(파일럿은 1개)로 했다. 자료 생성은 동시에 2개 프로세스 이하였다. 다만 공식 생성기가 내부에서 부르는 ffmpeg는 자체 기본 스레드 수를 쓴다(생성기를 고치지 않으려고 그대로 뒀다).
- 백그라운드 작업은 PID로만 종료했다.

- `gen_data.py`, `gen_synth.py`, `synth.py`, `gen_val.py`: 자료 생성. `train.py`: 학습. `eval_val.py`: 최종 검증.
- `model.pt`(= `model_v2.pt`, 최종), `pilot.pt`, `logs/`, `data/`(특징 npz), `val_data/`(검증 mp4와 메타데이터).
