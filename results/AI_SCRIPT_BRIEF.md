## 0. 실험 구조 (대본 도입부용)

- 캡차 5종을 웹 게임으로 만들고(GitHub Pages, 설치 없이 브라우저), 유튜버(사람)와 AI(Claude)가 같은 문제를 푼다.
- 외부 웹사이트·다른 회사 AI API는 쓰지 않았다. 문제는 시드로 고정(사람과 AI가 같은 문제), 정답은 평문 없이 HMAC 해시로만 저장·채점.
- AI는 두 가지 방식으로 시험했다.
  - **A. 직접 보고 풀기**: 범용 AI가 아무 준비 없이 그림·영상을 '눈으로' 보고 답함. 코드 사용 금지.
    → 논문들이 말하는 "AI는 이 캡차를 못 푼다"와 같은 조건.
  - **B. 전용 봇 학습**: 현실의 캡차 공격자처럼, 그 캡차 하나만 노린 모델을 학습시켜 풂.
- 공정성 장치
  - 테스트마다 별도 AI(서브에이전트)를 새로 띄움 → 기억이 섞이지 않음 (예: 미션 2 원본 그림 / 흐린 그림은 서로 다른 AI).
  - B에서 시험 문제는 학습이 끝날 때까지 AI의 작업 폴더에 아예 없음. 채점은 따로.
  - B에서 공격자에게 주는 자료는 '현실의 공격자가 구할 수 있는 만큼'만:

| 경우 | 현실 근거 | 해당 미션 | AI에게 준 것 |
|---|---|---|---|
| 캡차 생성 코드가 공개됨 | 공격자도 같은 코드로 정답 달린 연습 문제를 무한정 만들 수 있음 | 1 (lepture/captcha), 4 (MVCAP 공식 코드) | 공개 코드만. 자료는 AI가 다른 시드로 직접 생성 |
| 생성 코드가 비공개 | 실제 캡차를 모아 사람에게 정답을 달게 함 (라벨링 업체) | 2 (착시 캡차), 3 (IllusionAudio, 공식 코드 비공개) | 시험과 다른 시드로 만든 '정답 달린 캡차' (2: 3,000장, 3: 2,000개) |

  - B는 반드시 '학습한 모델'이어야 하고, 학습 전에 자료 일부를 떼어 두고 그걸로 먼저 정답률을 잼.

## 2. 미션 1: 글자 캡차

**캡차 원리**: 찌그러진 글자 이미지(대문자+숫자 5글자). 파이썬 공개 라이브러리 lepture/captcha(BSD-3)로 생성.
사람 규칙: 60초 안에 10문제 연속 정답, 틀리면 연속 0.
설계 근거: 대소문자 구분 안 함(구분하지 않으면 사람 정답률이 크게 오른다는 연구), 헷갈리는 글자(0/O, 1/I)는 줄임(사용성 연구 권고).

**A 직접 보기**: 20문제 64초, 11개 정답, 최고 연속 3 → 실패.
AI 본인 보고: 0과 O, 1과 I, 끊긴 획에서 헷갈림.

**B 전용 봇 — 원리**
- 라이브러리가 공개돼 있으니 AI가 같은 라이브러리로 연습 캡차를 직접 만듦 (시험과 다른 시드).
- 학습 자료: 캡차 30만 장 (헷갈리는 글자를 일부러 더 많이 넣음). 검증 1만 장, 최종 시험용 1만 장은 따로.
- 모델: CNN(이미지 특징) + 1D 합성곱 시퀀스 헤드 + CTC 손실(글자 위치를 따로 알려 주지 않아도 순서대로 읽는 학습법). 파라미터 145만 개.
- 과정에서의 판단:
  1. 첫 모델(CNN+GRU)은 너무 느려(초당 64장) 중단 → 원인을 재 보니 GRU가 40% → 1D 합성곱으로 교체.
  2. 이 CPU가 bf16(저정밀 계산)을 지원하는 걸 찾아내 학습 속도 약 3배.
  3. 남은 오류 75건 중 67건이 숫자 0 ↔ 대문자 O 혼동 → 그 글자만 다시 판정하는 '0/O 전문 분류기'를 따로 학습(24만 장).
- 정답률 변화(검증 1만 장, 5글자 전체): 92.4% → 97.7% → 98.4% → 99.2% → 99.25% → 전문 분류기 추가 후 **99.72%**
- 남은 오류 28장 중 21장이 0/O. AI 의견: "이 글꼴은 0과 O가 사람 눈으로도 거의 같다."
- 시험: 1분 안에 200문제 중 199개. 문제당 약 0.01초.

## 3. 미션 2: 착시 캡차

**캡차 원리**
- IllusionCAPTCHA(Ding 외, arXiv 2502.05461, 2025) 방식. 논문은 AI 그림 모델로 착시 그림을 만들지만, 여기서는 외부 모델 없이
  '하이브리드 이미지'(Oliva·Torralba·Schyns, SIGGRAPH 2006)로 구현.
- 하이브리드 이미지 = 글자 그림의 '저주파'(크게 흐린 것) + 나뭇잎·숲·풀밭 그림의 '고주파'(세부 무늬).
  가까이 보면 그림만, 눈을 가늘게 뜨거나 멀리서 보면 글자가 보임.
- 선택지 4개: 숨은 두 글자 낱말(정답) + 그림을 만들 때 쓴 장면 문구(논문의 함정 선택지) + 정답과 첫 글자가 같은 낱말 2개(사과/사고/사자 등).
- 논문 수치: 사람 23명 중 86.95% 첫 시도 통과, GPT-4o·Gemini는 실패.
- 사람 규칙: 60초 안에 10연속 정답.

**A 직접 보기**
- 원본 그림: 20문제 92초, 9개 정답 → 실패. AI 보고: "숲·나뭇잎 그림은 무늬가 너무 복잡해 획을 거의 못 봄, 대부분 찍음."
- 흐리게 줄인 그림(눈을 가늘게 뜬 효과): 20문제 71초, 18개 정답 → 연속 10 미달 + 60초 초과로 실패.
  → '흐리게 보는' 단계만 있으면 범용 AI도 글자를 읽는다는 점이 드러남.

**B 전용 봇 — 원리**
- 생성 코드가 비공개라는 설정 → 정답 달린 캡차 3,000장을 줌(라벨링 업체에서 산 것에 해당). 600장은 먼저 떼어 둠.
- AI가 스스로 찾은 핵심: 그림을 작게 줄이고 흐리게 한 뒤 큰 얼룩을 빼면 글자만 또렷이 남음 ("눈을 가늘게 뜨는 것과 같다").
  여기에 작은 꽃·잎 점을 지우는 필터(메디안)를 추가.
- 모델: 음절 단위로 읽는 CNN 2개(첫 음절·둘째 음절), 앙상블. 선택지마다 '첫 음절 확률 × 둘째 음절 확률'로 점수.
  처음 보는 음절이 나오면 글꼴로 글자를 그려 비교하는 대비책.
- AI가 정답 자료에서 알아낸 것: **'장면 설명 선택지는 한 번도 정답이 아니다'** → 후보에서 아예 뺌. (실제 공격자가 쓰는 방식)
- 시도: 글꼴 비교만(학습 없음) 25% → 크기 고쳐 95% → CNN 99.7%('기차'를 '기자'로 1개 틀림) → 해상도↑+점 제거 100%.
- 결과: 떼어 둔 600/600, 시험 원본·흐린 그림 각 200/200. 문제당 약 0.04초.

## 4. 미션 3: 소리 착시 캡차

**캡차 원리**
- IllusionAudio(arXiv 2601.08516, 2026) 방식. '사인파 음성(sine-wave speech, Remez 외 1981)': 말소리에서 공명 주파수(포먼트) 몇 줄만
  뽑아 순수한 사인파 3~4개로 다시 만든 소리. 처음 들으면 '삐-뿌-' 하는 기계음인데, 원래 말을 한 번 들으면 갑자기 말로 들림(착시).
- 논문처럼 깨끗한 원본을 먼저 들려주고(귀를 여는 역할), 사인파 소리 4개가 자동으로 차례로 나옴 → 같은 문장 고르기.
  논문의 '되돌릴 수 없는 무작위 다운샘플링'은 값이 비공개라 비슷한 방식(분석 프레임 무작위로 붙잡기)으로 구현.
- 사인파 변환 코드: johnhw/sinewave_speech(MIT). 원본 목소리: 유튜버 윈도우 PC의 내장 한국어 음성(TTS).
- 문장 24개(9글자 문장 20개 + 영상용 홍보 멘트 4개 "구독 눌러주시면 제 기분이 좋아져요" 등). 오답은 낱말이 겹치는 문장 위주.
- 논문 수치: 사람 63명 첫 시도 100%, 실험한 AI 공격 0%.
- 사람 규칙: 5문제, 하나라도 틀리면 실패. 시간 제한 없음(논문도 통과율로 평가). 화면의 '고르는 시간'은 소리가 나오는 동안 멈추는 보조 기록.

**A**: AI는 소리를 들을 수 없어 제외(처음 사양대로).

**B 전용 봇 — 원리**
- 생성 코드 비공개 설정 → 정답 번호만 달린 문제 2,000개를 줌(문장 글자는 안 줌). 400개는 먼저 떼어 둠.
- 특징: 소리를 주파수-시간 그림(로그 멜 스펙트로그램)으로 바꾸고 앞뒤 무음을 자름.
- 정렬: DTW(동적 시간 정렬) — 말하는 속도·시작 위치가 달라도 두 소리를 시간축으로 맞춰 비교하는 방법.
- 학습: '원본용'과 '사인파용' 신경망 인코더를 따로 두고(샴 네트워크), 같은 문장이면 가깝게·다른 문장이면 멀게 되도록 학습.
  즉 '깨끗한 목소리'와 '사인파 소리' 사이의 번역 규칙을 데이터로 배움.
- AI 자체 평가: "학습 없이 DTW만으로도 거의 다 맞힌다 → 이 캡차는 전용 공격에 약한 편." (우리 버전은 문장 24개·목소리 1개라 더 쉬움)
- 결과: 떼어 둔 400/400, 시험 24/24. 문제당 약 0.09초. 녹화 영상에서 고르는 시간 2.5초(대부분 마우스 이동).
- 에피소드: 초기 버전에서 AI가 **'정답 소리만 원본과 파일 길이가 똑같다'는 허점**을 발견(사용은 안 함) → 소리 4개 길이를 맞추고
  앞 무음을 무작위로 바꿔 고침. 고친 뒤 그 허점에 맞춰져 있던 예전 풀이기는 24문제 중 16개로 떨어짐.

## 5. 미션 4: 움직여야 보이는 캡차 (MVCAP L1)

**캡차 원리**
- MVCAP(Motion Vision CAPTCHA, "Invisible in Space, Visible in Time", ACM Multimedia 2026). 공식 코드(MIT)를 고치지 않고 사용.
- 검은 화면에 흰 점이 가득한 3초 영상(488×488, 30fps). 배경 점은 오른쪽으로(+2픽셀/프레임), 글자 모양 안의 점은 왼쪽으로(−2픽셀/프레임).
  **멈춘 한 장면에서는 흩어진 점뿐**이고, 움직여야 4글자가 보임(사람 뇌의 '움직임으로 형태 보기' 능력).
- 6지선다. 사람 규칙: 60초 안에 6문제 모두 정답.

**A 직접 보기**
- 정지 프레임 1장: 12문제 중 2개 → 찍기 수준(1/6). AI 보고: "모두 흩어진 점, 글자 일부조차 안 보임."
- 연속 프레임 8장: 12문제 중 2개 → 찍기 수준. AI 보고: "사진을 한 장씩 보는 방식이라 움직임을 지각할 수 없었다."
  → 논문 주장(사진 한 장씩 보는 AI 에이전트는 못 푼다)과 일치.

**B 전용 봇 — 원리**
- 공식 코드가 공개돼 있으니 AI가 그 코드로 정답 달린 영상을 직접 생성(실제 영상 2,000개 + 같은 방식의 메모리 합성 4,000개, 시험과 다른 시드).
- 핵심 아이디어: 연속 프레임을 '배경이 +2 움직였다'고 가정해 맞춰 본 차이와 '글자가 −2 움직였다'고 가정해 맞춰 본 차이를 비교
  → 89쌍 평균을 내면 글자 영역만 밝게 드러난 지도가 생김(움직임 보정 잔차).
- 그 지도를 입력으로 4글자를 읽는 CNN을 학습(248만 파라미터, 자리마다 32글자 중 하나). 선택지는 확률이 가장 높은 것.
- 시도: 영상 500개로 학습한 파일럿은 4글자 정확 62%(6지선다는 다 맞음) → 자료를 늘려 100%.
- 결과: 떼어 둔 300/300 (선택지 없이 4글자를 그냥 읽어도 300/300), 시험 36/36. 문제당 약 0.5초.

## 6. 미션 5: ARC-AGI-3

**원리**
- ARC Prize의 ARC-AGI-3: 설명이 전혀 없는 처음 보는 퍼즐 게임을, 화면을 보며 직접 해 보고 규칙을 알아내 푸는 시험.
  '얼마나 빨리 배우나'를 재는 것이 목적. 공식 게임 3개(LS20, FT09, VC33, 총 20단계), 공식 게임 엔진을 브라우저 안 파이썬(Pyodide)으로 그대로 실행.
- 공식 규칙: 시간 제한 없음. 단계마다 행동 상한 = 공식 사람 기준 행동 수 × 5 (넘으면 그 게임 끝).
  점수 = 깬 단계 + 사람 대비 행동 효율. 사람 기준 = 처음 해 보는 여러 사람의 상위 중간값(ARC Prize 공식 값, 게임 파일에 포함).
  행동 상한을 두는 이유: 무작위로 수없이 눌러 우연히 깨는 것(찍어서 찾기)을 막고 '배우는 효율'을 재려고.
- 사람(유튜버) 규칙: 30분 타이머 안에 3게임 모두 완료.
- 전용 봇을 학습시키지 않음: 게임별 봇을 만들면 '처음 보는 문제를 푸는 능력' 시험의 의미가 사라짐.

**AI 플레이 (공식 방식, 규칙을 모르는 새 AI)**
- 결과: **20단계 모두 클리어**, 행동 721번, 45분 41초, 상한 초과 없음. 30분 시점에는 13/20.
- 단계별 AI 행동 수 / 공식 사람 기준
  - LS20: 15, 45, 43, 47, 52, 98, 128 / 22, 123, 73, 84, 96, 192, 186
  - FT09: 4, 7, 14, 16, 21, 13 / 43, 12, 23, 28, 65, 37
  - VC33: 13, 7, 24, 26, 79, 20, 49 / 7, 18, 44, 61, 131, 34, 152
  - VC33 1단계(사람 7, AI 13)를 빼면 모든 단계를 사람 기준보다 적은 행동으로 깸.
- AI가 설명 없이 알아낸 규칙
  - LS20: 5칸씩 움직이는 블록. 왼쪽 아래 '열쇠'의 모양·색·방향을 문 안 무늬와 맞춘 뒤 문에 들어가면 통과. 흰 십자=회전, 흰 칸=모양 바꿈,
    4색 칸=색 바꿈, 노란 칸=에너지 충전, 벽 옆 회색 선=반대쪽 벽까지 미끄러짐. 7단계는 주변만 보이는 안개 → 지도를 기억하며 탐색.
    틀린 가설: "목숨을 잃어도 진행이 유지된다"(실제로는 단계가 처음부터). 7단계에서 에너지 계획 실수로 목숨 1개 잃음.
  - FT09: 단서 칸의 3×3 미니 무늬 = 주변 8칸 규칙(흰색=가운데와 같은 색, 연회색=다른 색). 클릭하면 색이 순서대로 바뀜.
    5·6단계는 한 번에 여러 칸이 같이 바뀌는 칸 → 아래 줄부터 클릭 수를 계산해 풂.
  - VC33: 칸막이로 나뉜 수조. 파란 버튼으로 물을 옆 칸에서 끌어옴. 부표의 색 띠를 같은 색 표시 높이에 맞추면 통과.
    4단계부터 칸막이 '문': 양쪽 수위가 같으면 문이 열려 부표가 건너감.
- 밝혀 둘 점: AI는 화면 그림만 읽는 보조 스크립트(픽셀을 글자로 출력, 바뀐 칸 표시, 안개 지도 기억)를 스스로 만들어 씀.
  게임 내부 정보·미리 시뮬레이션은 없음. 순수한 '눈으로만 보기'는 아님.
- 이전 시도(잘못된 조건): 공식 규칙에 없는 '전체 행동 300번' 상한을 둬서 12분 53초에 강제로 멈춤 → 12/20. 기록용으로만 남김.

## 7. 해석 주의 (대본에 꼭 반영)

1. 논문들의 "AI는 못 푼다"는 범용 AI가 처음 보고 바로 푸는 경우(A)다. 우리 A 결과도 미션 1·2·4 모두 실패로 같다.
2. 전용 봇(B)이 모두 뚫은 것은 '우리 실험 조건'의 결과다.
   - 우리 버전은 단순화됨: 미션 2는 AI 그림 모델 대신 하이브리드 이미지(그림 다양성 적음), 미션 3은 문장 24개·목소리 1개.
   - 공격자에게 정답 달린 자료·생성 코드를 공짜로 줌(현실은 수집·라벨링 비용이 듦).
   - 실제 서비스는 문제를 계속 바꾸고, 마우스 움직임 같은 행동 분석·요청 횟수 제한을 함께 씀 → 현실의 성공률은 이보다 낮을 것.
   - IllusionAudio 논문도 '사인파 음성으로 따로 학습한 공격자는 평가하지 않았다'고 한계로 밝힘.
3. 글자 캡차가 전용 학습에 뚫리는 건 현실에서도 반복된 일: 2013년 구글 연구팀이 reCAPTCHA의 가장 어려운 글자 캡차를 99.8% 풀었다고 발표.
4. 미션 5는 공식 방식 기준 성공이지만, 사람용 30분 규칙으로는 13/20(실패). 비교할 때 기준을 분명히 말할 것.
5. 영상 속 AI 시간에는 화면에서 마우스로 누르는 모습(일부러 넣은 짧은 간격)과 미션 3 소리 재생 시간이 포함됨. 순수 계산 시간은 위 표 참고.
