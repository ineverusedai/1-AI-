# AI(Claude) 테스트 결과 정리

사람 기록은 사람이 직접 플레이한 브라우저에서 **Shift + D**로 내려받은 CSV를 `results/`에 넣으면 같은 형식으로 합쳐진다.
아래는 Claude 쪽 결과다. 모든 수치는 `results/summary.csv`, `results/answers.csv`에 그대로 있다.

## 시험 방식과 공정성 규칙
- 정답은 HMAC 해시로만 저장. 채점은 해시 비교로만 한다.
- 테스트마다 별도 AI(서브에이전트)를 띄워 기억이 섞이지 않게 했다 (예: 미션 2 원본 그림과 흐린 그림은 서로 다른 AI).
- **(A) 직접 보고 풀기**: 범용 AI가 아무 준비 없이 그림·영상을 보고 답한다 (코드 금지). 논문들이 말하는 "AI는 못 푼다"와 같은 조건.
- **(B) 전용 봇 학습**: 현실의 공격자처럼 그 캡차 하나만 노린 모델을 학습시킨다. 미션 1~4 모두 같은 규칙:
  1. 시험 문제는 학습이 끝날 때까지 AI가 볼 수 없다 (작업 폴더에 없음, 채점은 따로).
  2. 학습 자료 일부를 떼어 두고 학습·튜닝에 쓰지 않은 그 자료로 먼저 검증한다.
  3. 공격자에게 주는 자료는 **현실에서 구할 수 있는 만큼만**:

| 경우 | 현실 근거 | 미션 | AI에게 준 것 |
|---|---|---|---|
| 생성 코드가 공개됨 | 공격자도 같은 코드로 정답 달린 연습 문제를 무한정 만들 수 있음 | 1 (lepture/captcha), 4 (MVCAP 공식 코드) | 공개 생성 코드만. 자료는 AI가 다른 시드로 직접 만듦 |
| 생성 코드가 비공개 | 실제 캡차를 모아 사람이 정답을 달아야 함 (라벨링) | 2 (이 프로젝트의 착시 캡차), 3 (IllusionAudio, 공식 코드 비공개) | 시험과 다른 시드로 만든 '정답 달린 캡차' (2: 3,000장, 3: 2,000개) |

  미션 2·3의 정답 달린 자료는 낱말·문장 목록과 목소리는 실제 서비스처럼 같고, 그림·소리 파일 자체는 시험 문제와 다르다
  (실제 공격자가 모으는 캡차도 같은 목록에서 나오기 때문).

## 미션별 메모

### 미션 1: 글자 캡차
- A: 0/O, 1/I 같은 글자와 끊긴 획에서 많이 틀렸다고 AI가 직접 보고했다.
- B: 공개 라이브러리로 시험과 다른 시드의 캡차 30만 장을 만들어 CNN 학습. 기록: `ai_solutions/m1_B/notes_B.md`

### 미션 2: 착시 캡차
- A: 원본 그림은 무늬 때문에 대부분 찍었고(9/20), 흐리게 줄인 그림에서는 글자가 보였다(18/20). 사람이 눈을 가늘게 뜨는 것과 같은 효과.
- B: AI가 스스로 '그림을 줄이고 흐리게 하기'와 '장면 설명 선택지는 늘 오답'을 찾아냄. 기록: `ai_solutions/m2_B/notes_B.md`

### 미션 3: 소리 착시 캡차
- B: 정답 번호만 달린 2,000개 중 400개를 먼저 떼어 두고 학습. 학습한 신경망 인코더(원본·사인파용 따로) + DTW 정렬로 비교.
  AI 보고: 학습 없는 DTW만으로도 대부분 맞힐 수 있어 이 캡차는 전용 공격에 약한 편.
- 이 과정에서 발견해 고친 허점: 처음 버전은 정답 소리만 원본과 길이(샘플 수)가 같았다. 소리 4개 길이를 같게 맞추고 앞 무음을 무작위로 바꿔 고침.
- 기록: `ai_solutions/m3_B/notes_B.md`

### 미션 4: 움직여야 보이는 캡차 (MVCAP L1)
- A: 정지 프레임이든 연속 프레임 8장이든 "흩어진 점만 보였다"고 보고했고 결과도 찍기 수준. 논문의 주장과 같다.
- B: 공식 생성기로 실제 영상 2,000개 + 같은 방식의 메모리 합성 4,000개를 만들어, '배경 +2px / 글자 −2px' 움직임 특징 위에 글자를 읽는 CNN을 학습. 선택지 없이 글자만 읽어도 떼어 둔 300개 모두 정답.
- 기록: `ai_solutions/m4_B/notes_B.md`

### 미션 5: ARC-AGI-3
- **공식 방식**(ARC Prize): 시간 제한 없음, 단계마다 행동 상한 = 사람 기준 행동 수(게임 파일의 공식 baseline) × 5, 넘으면 그 게임 끝.
  점수는 깬 단계 수 + 사람 기준 대비 행동 수(효율). 생각·화면 보기는 행동으로 세지 않음.
  (외부 검토 자료에는 '사람 기준 × 5에서 멈춤'으로만 나와 있어, 상한을 단계마다 적용했다.)
- 규칙을 모르는 새 AI가 `tools/arc_play.py`로 화면을 보고 행동을 골랐다 (한 번에 최대 10개 입력, 모든 행동에 시각 기록). 작업 시간 상한 2시간.
- 결과: **세 게임 20단계 모두 클리어, 상한 초과 없음**. 기록을 처음부터 다시 실행해 같은 결과가 나오는 것을 확인했다.

| 게임 | 단계별 AI 행동 수 | 사람 기준 (공식) |
|---|---|---|
| LS20 | 15, 45, 43, 47, 52, 98, 128 (합 428) | 22, 123, 73, 84, 96, 192, 186 |
| FT09 | 4, 7, 14, 16, 21, 13 (합 75) | 43, 12, 23, 28, 65, 37 |
| VC33 | 13, 7, 24, 26, 79, 20, 49 (합 218) | 7, 18, 44, 61, 131, 34, 152 |

  VC33 1단계를 빼면 모든 단계에서 사람 기준보다 적은 행동으로 깼다. 사람 기준은 '처음 해 보는 사람'의 상위 중간값이고,
  AI는 화면 그림을 읽는 보조 스크립트(픽셀을 글자로 출력, 바뀐 칸 표시, 안개 단계 지도 기억 등)를 스스로 만들어 썼다
  (frame.png 만 읽음, 게임 내부·시뮬레이션 없음). 순수한 '눈으로만 보기'는 아니라는 점을 밝혀 둔다.
- AI가 알아낸 규칙 (게임 설명 없음): LS20 = 열쇠 모양·색·회전을 문 무늬와 맞춰 들어가기(십자=회전, 흰 칸=모양, 4색 칸=색, 노란 칸=에너지, 7단계는 안개),
  FT09 = 3×3 미니 무늬(흰=같은 색, 연회색=다른 색)대로 칸 칠하기, VC33 = 칸막이 수조의 물을 옮겨 부표 색 띠를 같은 색 표시에 맞추기.
- 사람용 30분 규칙으로 보면: 30분 시점에 13/20단계.
- **이전 시도 (잘못된 조건)**: 공식 규칙에 없는 '전체 행동 300번' 상한을 임의로 둬서 12분 53초에 강제로 멈춤 → 12/20. 기록만 남김 (`ai_solutions/m5_A/`).
- 기록: `ai_solutions/m5_A_official/log.jsonl`, 보조 스크립트도 같은 폴더.
