# AI(Claude) 테스트 결과 정리

사람 기록은 사람이 직접 플레이한 브라우저에서 **Shift + D**로 내려받은 CSV를 `results/`에 넣으면 같은 형식으로 합쳐진다.
아래는 Claude 쪽 결과다. 모든 수치는 `results/summary.csv`, `results/answers.csv`에 그대로 있다.

공정성 규칙(모든 테스트 공통)
- 정답은 HMAC 해시로만 저장. AI는 `ai_test/` 복사본(또는 그 복사본만 든 작업 폴더)만 보고, 생성 코드·시드·키·정답을 보지 않는다.
- 문제마다 별도 AI(서브에이전트)를 띄워 기억이 섞이지 않게 했다 (예: 미션 2 원본 그림과 흐린 그림은 서로 다른 AI).
- (A) 직접 보고 풀기 = 코드 없이 그림을 보고 답함. (B) 코드로 풀기 = AI가 분석·학습 프로그램을 짜서 풂.

## 미션별 메모

### 미션 1: 글자 캡차
- A: 0/O, 1/I 같은 글자와 끊긴 획에서 많이 틀렸다고 AI가 직접 보고했다.
- B: 시험과 다른 시드로 만든 캡차 30만 장으로 CNN을 학습(3시간 44분). 검증 1만 장 5글자 전체 정답률 99.72%. 기록: `ai_solutions/m1_B/notes_B.md`

### 미션 2: 착시 캡차
- A: 원본 그림은 무늬 때문에 대부분 찍었고(9/20), 흐리게 줄인 그림에서는 글자가 보였다(18/20). 사람이 눈을 가늘게 뜨는 것과 같은 효과.
- B: 시험과 다른 시드로 만든 정답 달린 캡차 3,000장으로 학습(약 1시간 40분, 자료 생성 20분 별도). AI가 스스로 '그림을 줄이고 흐리게 하기'와 '장면 설명 선택지는 늘 오답'을 찾아냄. 기록: `ai_solutions/m2_B/notes_B.md`

### 미션 3: 소리 착시 캡차
- AI는 소리를 들을 수 없어 B만 했다 (사양대로).
- **1차 풀이 AI가 허점을 발견**: 정답 소리만 원본과 길이(샘플 수)가 같았다. AI는 이 허점을 쓰지 않았지만, 문제를 고쳤다
  (소리 4개 길이를 같게 맞추고 앞 무음을 무작위로). 1차 풀이기는 고치기 전 자료(앞 무음 없음)에 맞춰 만들어져 고친 자료에서 16/24.
- 2차: 새 AI가 고친 자료로 다시 개발(약 20분). MFCC·로그멜·포먼트 DTW와 '원본으로 사인파를 직접 합성해 비교'를 합친 방법으로 24/24.
  AI가 발견해 **쓰지 않은** 준-지름길: 무음을 뺀 발화 길이가 원본과 가장 비슷한 보기가 정답과 22/24 일치 (같은 문장이면 길이가 비슷한 것은 소리 자체의 성질).
- 녹화 영상에는 소리가 들어 있다: AI가 원본 듣기를 누르고(원본 길이만큼 재생) → 분석 → 고른 소리를 끝까지 재생 → 확인.
- 기록: `ai_solutions/m3_B/notes_B.md`, `ai_solutions/m3_B_v1/notes_B.md`

### 미션 4: 움직여야 보이는 캡차 (MVCAP L1)
- A: 정지 프레임이든 연속 프레임 8장이든 "흩어진 점만 보였다"고 보고했고 결과도 찍기 수준(2/12). 논문의 주장(사진 한 장씩 보는 AI는 못 푼다)과 같다.
- B: 블록 매칭으로 배경(+2px)과 글자(−2px)의 반대 움직임을 찾아 글자 마스크를 만들고, 선택지를 글꼴로 그려 비교. 36/36, 문제당 약 1초. 개발 17분.
- 기록: `ai_solutions/m4_B/notes_B.md`

### 미션 5: ARC-AGI-3
- AI가 `tools/arc_play.py`로 화면 그림을 보고 행동을 골랐다 (한 번에 최대 5개까지 이어서 입력 가능, 모든 행동에 시각 기록).
  제한: 30분, 행동 300번 (`config.json` m5). 295번 쓰고 12분 53초에 멈춤 — 시간이 아니라 행동 상한에 걸림.
- AI는 화면 그림(frame.png)을 64×64 글자 격자로 바꿔 주는 작은 스크립트를 스스로 만들어 같이 봤다 (게임 내부 정보는 읽지 않음). 순수한 '눈으로만 보기'는 아니라는 점을 밝혀 둔다.
- AI가 알아낸 규칙 요약 (게임 설명은 없었음):
  - FT09: 단서 칸의 흰/회색 무늬 = 이웃 칸이 가운데 색이어야/아니어야 함. 클릭하면 팔레트 순서로 색이 바뀜. 6단계 모두 완료.
  - LS20: 열쇠 모양·색을 목표와 같게 바꾼 뒤 목표 칸으로. 흰 십자 = 회전, 색 칸 = 색 바꿈, 노란 막대 = 남은 이동, 흰 막대 = 반대쪽 벽까지 밀어냄. 3단계까지.
  - VC33: 파란 버튼으로 칸 사이 물(흰색)을 옮겨 색 버튼과 표시 높이 맞추기. 3단계까지.
- 리플레이 영상은 AI의 실제 행동 기록을 사람용 웹 화면에서 그대로 다시 입력해 찍었다. 생각하는 시간은 건너뛴 타임랩스(화면 위 남은 시간은 실제 시각대로 줄어듦).
- 기록: `ai_solutions/m5_A/log.jsonl`
